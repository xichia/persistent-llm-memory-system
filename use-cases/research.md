# Research

Sources, findings, hypotheses, and unresolved questions — kept separately from conclusions.

Research memory fails in two opposite ways: throwing every PDF snippet into the prompt, or keeping only a final answer and losing the trail. The tree splits those concerns.

## Layout

For project-bound research, use the project's `research.md` (and logs for the messy middle).

For topics that will recur, use `knowledge/<topic>/`:

- What you currently believe
- Sources (links, citations, primary texts)
- Hypotheses still in play
- Unresolved questions
- Dead ends worth not repeating

## Separate the layers

| Layer | Where it lives | Changes when |
| --- | --- | --- |
| Source | listed under Sources | you find a document |
| Finding | notes / findings | evidence updates |
| Hypothesis | explicit list | tests land |
| Unresolved | open questions | you answer or abandon them |
| Decision | `decisions.md` | you commit |

A finding is not a decision. "Paper X suggests Y" can sit in research for months. It moves to `decisions.md` only when Y becomes how you will act.

## Retrieval

- Working on the question: load the topic folder + current `research.md`
- Need the trail: open dated logs or source list
- Need the call that was made: `decisions.md` only

Do not inject every source. Inject the structured note, then open a source if the task is to re-evaluate it.

## Unresolved questions are first-class

Leave them written down. They are some of the highest-value memory you can give a future session: "we still don't know whether…". A model that only sees past answers will fake closure.
